# Node.js Authentication System — API Specification

**Project overview:** A complete authentication system integrating 2FA (TOTP) and OAuth with Google and GitHub as providers.

**Stack:** Node.js · Express · PostgreSQL · Docker

---

## 1. Authentication

### `POST /auth/register`
Handles user registration. Sends a verification email.

**Request body**
```json
{
  "email": "string",
  "lastname": "string",
  "firstname": "string",
  "password": "string",
  "confirm_password": "string",
  "profil": "file (optional)"
}
```

**Response**
```json
{
  "success": true,
  "data": {
    "user": {
      "id": "string",
      "lastname": "string",
      "firstname": "string",
      "email": "string",
      "created_at": "date",
      "profil": "url",
      "email_verified_at": "date | null",
      "disabled_at": "date | null",
      "role": "string"
    },
    "message": "Verification email sent !"
  }
}
```

---

### `POST /auth/login`
Handles user login. Returns an access token and sets an **HTTP-only cookie** containing the refresh token.

**Request body**
```json
{
  "email": "string",
  "password": "string"
}
```

**Response**
```json
{
  "success": true,
  "data": {
    "user": {
      "email": "string",
      "profil": "url",
      "lastname": "string",
      "id": "string",
      "role": "string",
      "firstname": "string",
      "created_at": "date",
      "disabled_at": "date | null",
      "email_verified_at": "date | null",
      "two_factor_enabled_at": "date | null"
    },
    "accessToken": "string"
  }
}
```

> If 2FA is enabled, the response instead returns `{ "success": true, "mfa_required": true, "user_id": "string" }`. See [2FA login](#post-auth2falogin).

---

### `POST /auth/logout`
Requires an authenticated user (valid access token **and** refresh cookie).

**Response**
```json
{
  "success": true,
  "message": "You're no longer connect !"
}
```

---

### `POST /auth/refresh`
No payload. The user must include the refresh token cookie.

**Response**
```json
{
  "success": true,
  "accessToken": "string"
}
```

---

## 2. Email Verification

### `GET /:id/verify/:token`
Consumes the verification link sent by email and activates the account if the token is still valid.

**Path parameters**
| Param | Type | Description |
|-------|------|-------------|
| `id` | string | User ID |
| `token` | string | Verification token |

**Response**
```json
{
  "success": true,
  "data": "Account successfully verified ! You can login."
}
```

---

## 3. Password Reset

### `POST /forgot-password`
Takes the user's email, sends a reset token by email.

**Request body**
```json
{
  "email": "string"
}
```

**Response**
```json
{
  "success": true,
  "data": {
    "user_id": "string",
    "message": "Reset password email successfully sent !"
  }
}
```

---

### `POST /auth/reset-password`
Completes the reset process initiated by `/forgot-password`.

**Request body**
```json
{
  "token": "string",
  "user_id": "string | number",
  "newPassword": "string"
}
```

**Response**
```json
{
  "success": true,
  "message": "Password successfully reset !"
}
```

---

## 4. OAuth

### `GET /auth/oauth-links`
Returns the authorization URLs to start OAuth with Google and GitHub. **No authentication required.**

**Response**
```json
{
  "success": true,
  "data": {
    "googleLink": "url",
    "githubLink": "url"
  }
}
```

---

### `GET /google/callback` · `GET /github/callback`
Read the authorization code from the provider. Registers the user if they do not exist, logs them in if they do.

**Query parameters**
| Param | Type | Description |
|-------|------|-------------|
| `code` | string | Authorization code from the provider |

**Response:** same as [`/auth/login`](#post-authlogin).

---

## 5. Two-Factor Authentication (2FA)

### `POST /auth/2fa/setup`
Requires authentication. Generates the TOTP secret and QR code.

**Response**
```json
{
  "success": true,
  "data": {
    "secret": "string",
    "dataUrl": "string"
  }
}
```

---

### `POST /auth/2fa/confirm`
Requires authentication. Validates the code generated by the authenticator app using the secret from the previous step.

**Request body**
```json
{
  "code": "string"
}
```

**Response**
```json
{
  "success": true,
  "message": "2FA successfully enabled !"
}
```

---

### `POST /auth/login` (when 2FA is enabled)
After enabling 2FA, a normal login returns a challenge instead of tokens:

```json
{
  "success": true,
  "mfa_required": true,
  "user_id": "string"
}
```

---

### `POST /auth/2fa/login`
Completes login by providing the current TOTP code.

**Request body**
```json
{
  "user_id": "string",
  "code": "string"
}
```

**Response:** same as the standard [`/auth/login`](#post-authlogin) response (with access token).

---

### `POST /auth/2fa/disable`
Requires authentication. Disables 2FA if enabled.

**Response**
```json
{
  "success": true,
  "message": ["Two factor disabled"]
}
```

## 6. User Profile

### `GET /users`
Requires authentication. Returns the current user's profile.

**Response**
```json
{
  "success": true,
  "data": {
    "id": "string",
    "email": "string",
    "firstname": "string",
    "lastname": "string",
    "email_verified_at": "date | null",
    "profil": "url",
    "two_factor_secret": "string",
    "two_factor_enabled_at": "date | null",
    "disabled_at": "date | null",
    "created_at": "date",
    "updated_at": "date | null",
    "role": "string"
  }
}
```

### `PATCH /users`
Requires authentication. Allows the user to update `email`, `lastname`, and `firstname`.

**Request body**
```json
{
  "email": "string (optional)",
  "lastname": "string (optional)",
  "firstname": "string (optional)"
}
```

**Response**
```json
{
  "success": true,
  "data": {
    "id": "string",
    "email": "string",
    "firstname": "string",
    "lastname": "string",
    "email_verified_at": "date | null",
    "profil": "url",
    "two_factor_enabled_at": "date | null",
    "disabled_at": "date | null",
    "created_at": "date",
    "updated_at": "date | null",
    "role": "string"
  }
}
```

## 7. Administration

### `GET /admin/sessions`
**Admin only.** Lists active sessions.

**Response**
```json
{
  "success": true,
  "data": [
    {
      "lastname": "string",
      "firstname": "string",
      "user_agent": "string",
      "ip_address": "string",
      "created_at": "date"
    }
  ]
}
```

---

### `GET /admin/histories`
**Admin only.** Returns the login history.

**Response**
```json
{
  "success": true,
  "data": [
    {
      "id": "string",
      "ip_address": "string",
      "user_agent": "string",
      "success": "boolean",
      "firstname": "string",
      "lastname": "string",
      "email": "string"
    }
  ]
}
```
